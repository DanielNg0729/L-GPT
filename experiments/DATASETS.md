# Datasets: what each one is, and how it was made

Every dataset in this repository is either **released by the organizer** or **generated by
us**. Nothing here is scraped, purchased, or taken from a third party, and nothing here is
private competition data. This document exists so that claim is checkable rather than
asserted.

Read it alongside [`INDEX.md`](INDEX.md), which lists the experiments, and
[`DECISION_LOG.md`](DECISION_LOG.md), which records what each measurement decided.

---

## 1. The rule everything follows

The released simulator builds every customer utterance from the target product's own
catalogue record. Every constraint the customer speaks is a **verbatim substring of the
target document**. That single fact shapes every corpus below: to test whether the agent
survives *wording* change, we have to perturb the wording without breaking that provenance
property, because breaking it would test a different task than the one being scored.

So the corpora split along two independent axes, and they are kept apart deliberately:

| axis | what changes | what stays verbatim | what it stresses |
|---|---|---|---|
| **template / wrapper** | the sentence around the value | the value itself | recognition, dialogue-act routing |
| **attribute / value** | the value itself | the sentence around it | catalogue attestation, deparaphrasing |

A suite that moved both at once would tell us something failed without telling us which
half. Where we do test both together, it is a separate, explicitly labelled suite.

---

## 2. Provenance rules we hold ourselves to

**Train and test never share strings.** Template banks are split by template family, not by
row, so a test wrapper is one the model has never seen in any form.

**The generator is never the solver.** Paraphrase corpora were generated with Claude Haiku
(Anthropic); the system under test uses GPT-OSS via Groq. If the same model family wrote
the test and answered it, a good score would measure self-consistency rather than
generalisation. `open_vocabulary/manifest.json` records this explicitly as
`generator_solver_independent: true`.

**Generated paraphrases are filtered before use.** Candidates are rejected when they share a
token with the canonical value, when the catalogue already attests them, when they appear in
an earlier suite, or when they are empty or over-long. The rejection counts are kept in the
manifest — for the open-vocabulary suite, 260 generated and 204 usable after 56 rejections.

**We do not tune against our own weaknesses.** These suites exist to find failures. Where a
suite has a known weakness (a small distinct-paraphrase pool, for instance), it is recorded
rather than exploited.

**Nothing derived from a private set exists here**, because we have never had one. Every
population proxy is resampled from the released catalogue, and every manifest carries
`truth_status: "participant-safe proxy; not organizer private data"`.

## 3. Organizer-released data

| path | rows | tracked | notes |
|---|---:|---|---|
| `data/public_set.jsonl` | 200 | yes | the released development sessions, byte-identical to the kit |
| `data/catalog.jsonl` | 50,000 | **no** | 60 MB; downloaded, not committed. See `data/README.md` |

Both are covered by [`UPSTREAM_INTEGRITY.sha256`](../UPSTREAM_INTEGRITY.sha256) and checked
by `python tools/verify_upstream_integrity.py`. The catalogue is excluded from the
repository for size, with its checksum recorded in `data/SHA256SUMS`.

The public set ships its intent cards **hidden**; the evaluator fills them from the target
product at run time via `materialize_hidden_fields`. Anything reading the cards straight off
disk sees empty ones — a mistake worth knowing about, because it silently produces
plausible-looking numbers.

## 4. Population-shift suites

**Why they exist.** The public set is 200 sessions drawn towards popular products. A private
set need not be. These resample the released catalogue under different target populations so
we can see which results are properties of the agent and which are properties of the sample.

**How they are made.** Targets are sampled without replacement with `P(target)` proportional
to `rating_number` raised to a weight exponent — 1.0 for the proxy, inverted for the
adversarial population, flat for uniform. Sessions are then rendered through the released
simulator's own message shapes. Full parameters, pool sizes and distribution quantiles are in
each directory's `manifest.json`.

| path | rows | what it models |
|---|---:|---|
| `datasets/sets/organizer_proxy_800.jsonl` | 800 | popularity distribution matched to the public set |
| `datasets/sets/catalog_review_distinct_800.jsonl` | 800 | review-weighted, targets disjoint from the public set |
| `datasets/sets/catalog_uniform_800.jsonl` | 800 | every product equally likely — no popularity prior to exploit |
| `datasets/sets/catalog_inverse_800.jsonl` | 800 | inverse popularity; an adversarial bound, not an expectation |
| `datasets/optuna_sets/*.jsonl` | 800 ×5 | held-out folds used for hyper-parameter search only |
| `datasets/independent_validation_sets/*.jsonl` | 800 ×12 | target-variance × popularity × replicate, for fold-noise estimation |
| `datasets/override_focus/override_focus_800.jsonl` | 800 | intent-change sessions concentrated, to stress rejection clearing |

Built by `studies/build_sets.py`, `studies/build_optuna_sets.py` and
`studies/build_independent_validation_sets.py`. Scored with
`tools/run_population_benchmark.py`.

## 5. Wrapper-paraphrase corpora (dialogue-act routing)

**Why they exist.** The recognition gate matches the simulator's literal message shapes. If a
private set reworded them, the gate would report "unfamiliar" without saying what the message
*means* — and two behaviours depend on meaning: clearing rejection state on an intent
override, and contributing nothing on a no-preference turn.

**How they are made.** A bank of wrapper templates per dialogue act, split by family so train
and test share **zero** template strings, then rendered around verbatim catalogue values. The
invariant is recorded in the manifest: *"Only wrappers change; all category and attribute
values remain verbatim."*

| path | rows | role |
|---|---:|---|
| `datasets/route_template_bank/train.jsonl` | 16,705 | training wrappers (72 shifted templates) |
| `datasets/route_template_bank/test.jsonl` | 9,600 | held-out wrappers (48 shifted templates) |
| `datasets/turn_gated_bank/final_test.jsonl` | 9,600 | final test with the turn mask applied |
| `datasets/route_classifier/{development,holdout}.jsonl` | 6,400 / 4,800 | six-way act classification |
| `datasets/route_actions/{train,holdout}.jsonl` | 5,200 / 2,600 | action-level split |
| `datasets/route_shift/*.jsonl` | 1,200 ×2 | wrapper distribution shift |
| `datasets/route_phrase_augmentation.jsonl` | 9,600 | train-only phrasing augmentation |

The augmentation set is **train-only and wrapper-disjoint** by construction — it may not
contain any phrasing that appears in a test bank.

## 6. Value-paraphrase corpora (attribute deparaphrasing)

**Why they exist.** The other axis. When the *value* is reworded — `cotton` becomes
`made from a soft plant fibre` — exact lookup cannot help, because the value has left the
catalogue's vocabulary entirely. These measure whether anything can recover it.

**How they are made.** Canonical attribute values are extracted from the catalogue into a
dictionary, an independent model paraphrases them, and the results are filtered as described
in §2 before being rendered into sessions.

| path | rows | role |
|---|---:|---|
| `datasets/open_vocabulary/review800_open_vocab_paraphrase.jsonl` | 800 | the main attribute-paraphrase suite |
| `datasets/open_vocabulary/review800_canonical_replay.jsonl` | 800 | the same sessions with values left canonical — the control |
| `datasets/open_vocabulary/review800_hostile_{canonical,paraphrase}.jsonl` | 710 ×2 | category removed, only paraphrased values remain |
| `datasets/public_value_only/official200_{attribute_paraphrase_dev,canonical_replay}.jsonl` | 200 ×2 | the same treatment on the released sessions |
| `datasets/catalogue_attribute_dictionary.jsonl` | 7,922 | canonical attribute values mined from the catalogue |
| `datasets/generated_shopper_paraphrases.jsonl` | 1,382 | raw generator output, before filtering |
| `datasets/generated_shopper_paraphrases.clean.jsonl` | 53 | what survived filtering |
| `datasets/broad_semantic_paraphrases.jsonl` | 7,922 | broad paraphrase sweep over the dictionary |
| `datasets/open_vocabulary_paraphrases.jsonl` | 260 | the generated pool for the open-vocabulary suite |

**The control set matters as much as the test set.** `review800_canonical_replay.jsonl` is
the same 800 sessions with values untouched, so any difference is attributable to the
paraphrasing rather than to the session sample.

The **hostile** suites remove the category as well, which is how we discovered the category
carries roughly two thirds of the task: with perfect canonical values but no category, the
achievable score collapses from 0.945 to 0.280.

## 7. Equivalence and synonym corpora

**Why they exist.** To ask whether two catalogue phrases mean the same thing — the training
signal for the encoder work, and the evaluation set for the verifier that was ultimately
rejected.

**How they are made.** Pairs are proposed from the attribute dictionary, then
**measurement-checked** against the catalogue rather than accepted on a model's say-so. Files
ending `_proposed` are candidates; `_measurement_checked` are the survivors. `_train_only`
files are quarantined from every test set. Each carries a `.report.json` with its acceptance
counts.

| path | rows | role |
|---|---:|---|
| `datasets/catalogue_equivalence_pairs_{proposed,measurement_checked}.jsonl` | 115 / 109 | pairwise equivalence |
| `datasets/catalogue_equivalence_clusters_{proposed,measurement_checked}.jsonl` | 50 / 50 | cluster-level equivalence |
| `datasets/catalogue_synonym_training.jsonl` | 3,626 | encoder training pairs |
| `datasets/catalogue_synonym_*_train_only.jsonl` | 7–171 | quarantined synonym sources |
| `datasets/sets/canonical_verification_negatives.jsonl` | 22,550 | hard negatives for the verifier |
| `datasets/sets/frozen_equivalence_verification.jsonl` | 134 | frozen evaluation set |
| `datasets/external_train_only_{canonicals,pairs}.jsonl` | 7,922 ×2 | externally sourced, train-only |

One correction worth recording: an early adversarial probe mined negatives as nearest
neighbours **of the proposal**, which made them true positives (`leather` → `leather
fabric`). The resulting AUROC of 0.5760 was void. Rebuilt with within-family cross-pairing,
it measured 0.8349.

## 8. Span-tagging corpora

**Why they exist.** Training data for the token classifier that separates product content
from conversational scaffolding.

| path | rows | role |
|---|---:|---|

Built by `studies/build_span_bert_data.py`. The two variants exist to separate "learned the

## 9. What is deliberately *not* tracked

| path | why |
|---|---|
| `data/catalog.jsonl` | 60 MB; downloaded, checksum in `data/SHA256SUMS` |
| `submission/models/`, `checkpoints/` | published to the Hugging Face Hub instead — see [`../docs/MODEL_ARTIFACT_POLICY.md`](../docs/MODEL_ARTIFACT_POLICY.md) |
| `datasets/prompt_arm_caches/`, `**/.*_cache*.json` | provider-response caches; per-experiment scratch, not results |

Git LFS was tried for the checkpoints and rejected: a history rewrite left a 134-byte
pointer in the working tree instead of the weights, and the agent kept scoring its usual
number because those layers are gated off clean traffic — a dead model reported as a healthy
run. Hub resolution fails loudly instead.

## 10. How to make another one

The recipe every suite above follows:

1. **Decide which axis you are perturbing**, and hold the other one fixed. A suite that moves
   both cannot attribute a failure.
2. **Keep a control.** Render the same sessions with no perturbation. Without it, a score
   difference could be the sample rather than the treatment.
3. **Split by family, not by row.** Splitting rows leaks: the same template appears on both
   sides with different values.
4. **Use a generator from a different family than the solver**, and record that you did.
5. **Filter, and keep the rejection counts.** A paraphrase sharing a token with its canonical
   is not testing paraphrase recovery.
6. **Write a `manifest.json`** with the parameters, the pool sizes, the rejection counts and
   the source checksums. Every claim in this document is traceable to one.
7. **State the weakness.** Our paraphrase pools are finite and our generators are ours;
   "generalises across our own synthetic variation" is a weaker claim than "generalises to
   real users", and we do not make the stronger one.

## 11. Reproduction

```bash
python experiments/studies/build_sets.py                  # population-shift suites
python experiments/studies/build_attribute_dictionary.py  # canonical attribute values
python experiments/studies/build_span_bert_data.py        # span-tagging corpora
python tools/run_population_benchmark.py                  # score the population suites
python tools/verify_upstream_integrity.py                 # organizer files unmodified
```

Suites that call an external generator need `GROQ_API_KEY` (or the relevant credential) and
are **not** required to reproduce any scored result. The deterministic pipeline needs none of
them.
