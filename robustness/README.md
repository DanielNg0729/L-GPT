# Internal robustness benchmark

This directory contains a participant-safe benchmark for testing population shift without
claiming access to organizer-private labels.

## Why the previous unseen-800 was revised

The original research benchmark sampled targets with replacement from all approximately
49,800 non-public catalogue products. It was useful as a different generalization test, but it
did not model two facts disclosed in the competition slides:

- only 1,406 distinct products are candidate targets;
- all 800 private targets are distinct and disjoint from the 200 public targets.

The exact remaining 1,206 candidate ASINs cannot be recovered from participant-visible
files. They depend on organizer-held eligible review records. Selecting the catalogue's
top 1,206 products would invent an unsupported eligibility rule and leak popularity more
aggressively than the organizer has disclosed.

`organizer_proxy_800` therefore uses a disclosed-cardinality proxy pool:

1. exclude all 200 public targets;
2. choose 1,206 distinct unseen products using `P(target) ∝ rating_number`, without replacement;
3. take a deterministic 800-target split from that pool;
4. apply the official 40/40/15/5 scenario mix and public simulator.

The numbering above deliberately has no model-fitting step. The 200-public distribution
cannot be imposed on 800 distinct targets: even the 800 most-reviewed catalogue products
have a median of about 4,219 reviews, below the public median of 6,846. Sampling with
replacement hid this depletion constraint and was the main defect in the earlier suite.

The manifest labels this honestly as a proxy, records its seeds and distributions, and
asserts zero overlap with public targets.

## Included sets

| Set | Purpose |
|---|---|
| `organizer_proxy_800` | Best participant-visible approximation of the disclosed private target universe |
| `catalog_review_distinct_800` | Catalogue-wide review-weighted generalization with distinct targets |
| `catalog_uniform_800` | Population shift where popularity is not predictive |
| `catalog_inverse_800` | Adversarial population where popularity points the wrong way |

The latter three are stress tests, not private-score forecasts.

## Build

With the catalogue decompressed at `data/catalog.jsonl`:

```bash
python -m robustness.build_sets
```

The builder writes four JSONL files and `robustness/sets/manifest.json`. Re-running it with
the same inputs produces byte-identical files.

## Evaluate

```bash
python -m robustness.run_benchmark
```

To run only the organizer-aligned proxy:

```bash
python -m robustness.run_benchmark --only organizer_proxy_800
```

LLM extraction and reranking are disabled by default for this benchmark. The local BERT
tagger remains available but is unreachable on normal simulator messages through the
recognition gate.

## Interpretation

Use `organizer_proxy_800` for realistic internal selection, but require a candidate change
to survive the uniform and inverse sets before calling it population-robust. Do not tune on
all four sets and then report the same sets as held out. If tuning resumes, create new seeds
and reserve at least one complete generated suite for final selection.
